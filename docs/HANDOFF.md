# 团队交接

## 当前责任

- 产品负责人：确认产品范围、主体/类目、隐私文本、费用、真机验收和最终发布。
- 开发维护者：实现功能与迁移、维护测试、处理依赖和安全告警。
- 发布执行者：按发布清单运行 CI、保存验证证据；不得绕过人工上传确认。

同一个人可以承担多个角色，但生产密钥、数据操作和发布动作仍需留下可审计记录。

## 新成员开始工作

1. 阅读 `README.md`、`docs/RELEASE_CHECKLIST.md`、`docs/ENVIRONMENTS.md` 和 `docs/ACCEPTANCE_TEST.md`。
2. 从 `.env.example` 创建个人开发配置，不复制 staging/production 密钥。
3. 安装后端依赖并运行 `sh scripts/verify.sh`。
4. 使用短期分支开发，不直接向 `main` 推送。
5. 数据模型变更必须新增 Alembic 迁移并确保 `alembic check` 通过。
6. 用户可见变化必须更新 `CHANGELOG.md`。

## 发布交接材料

- 本次版本号和变更说明；
- CI、依赖审计、包体和开发者工具检查结果；
- staging 真机回归记录；
- 数据库迁移及备份恢复点；
- 已知风险和回滚版本；
- 负责人对上传、审核和发布的明确确认。

## 紧急联系

正式发布前补充产品负责人、技术负责人和云平台支持渠道。禁止在本文写入密码、AppSecret、数据库口令或上传私钥。
