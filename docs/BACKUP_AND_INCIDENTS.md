# 备份与故障处理

## 备份原则

- 正式数据库至少每日自动备份，并开启加密。
- 备份与主数据库隔离保存，只允许最小权限账号访问。
- 保存周期在选择云平台后确定，并与隐私政策一致。
- 每季度在隔离环境进行一次恢复演练，记录恢复点和恢复耗时。
- 用户注销后，在线数据立即删除；备份副本在约定周期到期后清除。

CloudBase MySQL 当前内置自动备份每天一次、保留7天，个人版暂不支持控制台回档。若采用推荐的30天保存周期，必须另外配置每日加密逻辑备份到与数据库隔离的存储位置，并通过生命周期规则在第30天自动清除。任何备份任务都不得把数据库密码写入命令行、日志或仓库。

仓库提供 `scripts/backup_mysql.sh` 生成 AES-256 加密逻辑备份和 SHA-256 校验文件；`scripts/restore_mysql_staging.sh` 只允许恢复到 staging。脚本要求数据库客户端配置和加密口令文件权限均为 `0600`，不会在磁盘落明文 SQL。生产恢复不提供一键脚本，必须按当次故障范围单独审批。

## 恢复门禁

1. 每份备份记录时间、环境、迁移版本、校验值和到期日期。
2. 每月至少校验最新备份可读取；每季度在隔离环境完整恢复并运行 `alembic check` 与核心 API 测试。
3. 恢复演练不得连接正式小程序域名、发送消息或使用真实微信登录凭据。
4. 正式数据回档属于破坏性操作，必须由负责人当次确认，并在执行前再创建恢复点。

## 故障分级

- P0：大面积不可用、身份越权、密钥或个人数据泄露。立即停止相关入口并通知负责人。
- P1：核心记录无法保存、数据明显错误。暂停发布并启动回滚。
- P2：非核心页面或展示异常。评估影响后进入修复版本。

## 处理顺序

1. 确认影响范围并保留日志，不在日志中记录 AppSecret、会话令牌或完整个人资料。
2. 隔离故障组件；可能涉及泄露时先吊销会话，密钥轮换须负责人确认。
3. 回滚到最近稳定制品，验证健康检查与核心流程。
4. 修复后补充自动化测试，记录根因和预防措施。
5. 涉及个人信息事件时，根据适用法规和微信平台要求评估通知与报告义务。
